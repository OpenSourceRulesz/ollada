Verification notes

Verified WITH ollada's mask-dtype repair active (their generate_block hardcodes a bf16 mask; fp16-on-T4 needs it aligned — see adapters/diffcoder.py). Steps swept 2026-10-21 (sweep notebook v0.1.0, same prompt set): 64 steps COLLAPSES — repetition degeneration ('by by by...' on the bug-fix prompt, 'maps maps maps' on the hash-map prompt, early-EOS never fires); 128 steps: code fully correct but explanation prose has grammar artifacts ('accumulatinging', 'two couple of issues'); 256 steps (the default): same correct code, prose clean. Quality at the default: bug-fix excellent (both planted bugs diagnosed, corrected code right); palindrome code correct/clean but ignores the 'only output code' instruction (preamble + explanation added); hash-map exact. Known limit at ALL step counts: the model's verbose style (preamble + long docstring) exhausts the 256-token canvas mid-answer on the Fibonacci prompt — a gen_length question, not a steps question; a gen_length bump is future sweep material.
